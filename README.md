# coding-agents

My setup for coding agents: skills, base rules, and a sync script that drops it all into any repo I work in.

I bounce between Claude Code, Codex, and OpenCode. Maintaining three separate "how I want agents to behave" configs got old fast. This repo is the one place I edit them; everywhere else just pulls.

## What's in here

```
skills/      SKILL.md skills (the format Claude and Codex both read)
rules/       base rules that go into every project's AGENTS.md
bin/sync     install/refresh script
```

## Drop it into a project

```bash
git submodule add https://github.com/C-o-d-e-C-o-w-b-o-y/coding-agents.git .agent-config
.agent-config/bin/sync
git add . && git commit -m "Adopt coding-agents"
```

The sync script writes:

- `.claude/skills/*` and `.agents/skills/*` — symlinks to `.agent-config/skills/*`. Claude Code reads the first path, Codex reads the second; both point at the same skill content.
- `agents.local.md` — project-specific rules. Yours to edit.
- `AGENTS.md` — generated by concatenating `rules/base.md` and `agents.local.md`.
- `CLAUDE.md` — symlink to `AGENTS.md`.

Commit all of it, symlinks included.

## Pull in updates

```bash
git -C .agent-config pull
.agent-config/bin/sync
git commit -am "Sync coding-agents"
```

Skill changes propagate automatically through the symlinks. `AGENTS.md` rewrites itself with the new base.

## Add a skill

Drop a directory under `skills/` with a `SKILL.md` inside. Frontmatter needs `name` and `description`. That's it; next sync, every project sees it.

## Project-specific additions

`agents.local.md` is yours; it gets concatenated onto the base every sync. Don't edit `AGENTS.md` directly — it gets clobbered.

For skills that only make sense in one project, drop them straight into the consumer repo's `.claude/skills/<name>/` or `.agents/skills/<name>/`. They live alongside the symlinked shared ones. Names just have to differ.

## How agents find this stuff

Both Claude Code and Codex have settled on the same `SKILL.md` format, and both read `AGENTS.md` from the repo root (Claude Code via the `CLAUDE.md` symlink). Only the skill directory location differs (`.claude/skills` vs `.agents/skills`). Symlinking from one source into both paths is the whole trick.
