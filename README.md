# coding-agents

My setup for coding agents: shared skills, shared base rules, and a small installer that drops them into any repo I work in.

I bounce between Claude Code, Codex, and OpenCode. Maintaining three separate "how I want agents to behave" configs got old fast. This repo is the one place I edit them; everywhere else just pulls from here.

## What's in here

```text
skills/              Shared skills, one directory per skill
rules/               Base rules that go into every project's AGENTS.md
bin/coding-agents    Main CLI: install, update, doctor, list-skills, new-skill
bin/sync             Low-level sync script used by the CLI
```

## Mental model

This repo is the source of truth. Agent apps do not read it automatically.

The instructions model is:

- `rules/base.md` contains global instructions shared across repos.
- `<repo>/agents.local.md` contains instructions specific to one repo.
- `<repo>/AGENTS.md` is generated output: shared base plus repo-local additions.

Treat `AGENTS.md` as compiled output, not a source file.

You still need to install or sync it into each consumer repo. For Codex and Claude, that means creating repo-local entries under:

- `.agents/skills/`
- `.claude/skills/`

If a skill exists here but not in those directories in the consumer repo, the app will not see it.

The short version:

- `coding-agents` contains the shared skills and rules
- each project needs those files linked into the places the agent already scans
- after you add a brand-new skill, restart the app so it notices it

## Drop it into a project

```bash
git submodule add https://github.com/C-o-d-e-C-o-w-b-o-y/coding-agents.git .agent-config
.agent-config/bin/coding-agents install
git add . && git commit -m "Adopt coding-agents"
```

The installer writes:

- `.claude/skills/*` and `.agents/skills/*` — symlinks to `.agent-config/skills/*`. Claude Code reads the first path, Codex reads the second; both point at the same skill content.
- `.agent-local/skills/*` — optional repo-local skills, linked into both agent skill directories when present.
- `agents.local.md` — repo-specific instructions. This is the repo-local source file you edit.
- `AGENTS.md` — generated by concatenating `rules/base.md` and `agents.local.md`.
- `CLAUDE.md` — symlink to `AGENTS.md`.

Commit all of it, symlinks included.

## Pull in updates

```bash
.agent-config/bin/coding-agents update
git commit -am "Sync coding-agents"
```

That command pulls the latest `coding-agents` changes from GitHub with `git pull --ff-only`, then re-runs the installer in the current repo.

Skill changes propagate automatically through the symlinks. `AGENTS.md` rewrites itself from the current shared base plus the repo's `agents.local.md`.

## Verify an install

```bash
.agent-config/bin/coding-agents doctor
.agent-config/bin/coding-agents doctor . grill-me
```

This tells you:

- which shared skills exist in `coding-agents`
- which local-only skills exist in `.agent-local/skills`
- whether `AGENTS.md` and `CLAUDE.md` are wired up
- which skills are visible in `.agents/skills` and `.claude/skills`
- whether a specific skill such as `grill-me` is installed

If you just added or updated skills, restart the agent app afterward.

You can also run `doctor` without a skill name:

```bash
.agent-config/bin/coding-agents doctor
```

That gives you the general health check for the repo. Add a skill name only when you want to confirm one specific skill.

## Ask the agent

You do not need to remember the CLI if you are already working with an agent in the repo. Ask for the outcome you want:

```text
Install coding-agents into this repo.
Update coding-agents from GitHub and sync the latest skills.
Check why grill-me is not available in this repo.
Create a local-only skill called post-mortem-review for this repo.
```

Under the hood, the agent can run the same commands for you:

- `install` for first-time setup or re-sync
- `update` to pull the latest changes from GitHub and re-sync
- `doctor` to explain what is installed and what is missing
- `new-local-skill` to scaffold a repo-only skill

The one thing the agent cannot skip is app discovery. If you add a brand-new skill, restart the app afterward.

## Add a skill

Scaffold one with:

```bash
bin/coding-agents new-skill your-skill-name "Short description of when to use it"
```

That creates `skills/your-skill-name/SKILL.md` with the required frontmatter.

Then:

```bash
bin/coding-agents install /path/to/consumer-repo
```

Frontmatter needs `name` and `description`. That's it; next install, every project sees it.

## Add a local-only skill

For a skill that should live in exactly one consumer repo, scaffold it with:

```bash
.agent-config/bin/coding-agents new-local-skill . my-project-skill "Short description of when to use it"
```

That creates:

```text
.agent-local/skills/my-project-skill/SKILL.md
```

Then run:

```bash
.agent-config/bin/coding-agents install
```

The installer will symlink that local-only skill into both:

- `.agents/skills/`
- `.claude/skills/`

This is the easiest way to keep a repo-only skill in one place while still making it visible to both tools.

## Project-specific additions

`agents.local.md` is yours; it gets concatenated onto the shared base on every sync. Don't edit `AGENTS.md` directly — it gets regenerated.

On first adoption in a repo that already has a hand-written `AGENTS.md`, sync will try to preserve the repo-specific part by moving it into `agents.local.md` before generating the new `AGENTS.md`.

For skills that only make sense in one project, prefer `.agent-local/skills/<name>/`. It gives you one canonical place to edit them, and install keeps the Claude and Codex paths in sync.

## How agents find this stuff

Both Claude Code and Codex have settled on the same `SKILL.md` format, and both read `AGENTS.md` from the repo root (Claude Code via the `CLAUDE.md` symlink). Only the skill directory location differs (`.claude/skills` vs `.agents/skills`). Symlinking from one source into both paths is the whole trick.

## Commands

```bash
bin/coding-agents install [target-dir]
bin/coding-agents sync [target-dir]
bin/coding-agents update [target-dir]
bin/coding-agents doctor [target-dir] [skill-name]
bin/coding-agents list-skills
bin/coding-agents new-skill <skill-name> <description>
bin/coding-agents new-local-skill [target-dir] <skill-name> <description>
```
